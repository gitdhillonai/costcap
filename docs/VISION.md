# costcap: purpose, mission and vision

## Basis

Sources inspected on main September 30, 2026: README.md, root package.json when present, open issue bodies and existing docs/ARCHITECTURE.md when present. Also docs/product-spec.md or docs/requirements/sprs-sprint-v1.md.

## Who it serves

Agent developers and fleet operators.

## Purpose and problem

The purpose is to make the workflow below usable with clear evidence and limitations, instead of scattered or unsupported outputs.

Set cap > wrap command > inspect receipt; optional hosted fleet policy.

## Mission

Bound proxy-mediated spend and explain what was counted.

## Three-year vision (aspiration)

A transparent local spend guardrail with optional fleet policy, alert and audit views. This is a direction, not a delivery schedule or market forecast.

## How it makes money

Free MIT core plus spec-proposed $19/mo hosted dashboard.

Planned revenue is not collected revenue. Track actual orders/subscriptions, direct cost, successful user workflows and error/abandonment rates once activated. Unknown metrics remain unknown.

## Honesty boundary

Model-price drift, streaming/concurrent accounting and proxy bypass. Coverage only includes mediated traffic; guardrails, not bill insurance.
