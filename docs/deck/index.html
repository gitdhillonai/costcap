CostCap · development beta

Stop the next agent call when the budget is already spent.

A local proxy meters provider-reported usage, writes a receipt, and refuses further calls at the cap. Guardrails, not a bill guarantee.

Problem

An agent retry loop can spend a day's budget before anyone looks at the provider invoice. Missing usage is easy to treat as free. A kill switch that only lives in one terminal does not cover the next process.

What exists

  • CLI wrap, day and month caps, step budget, retry-spiral detector, velocity breaker, and a local kill file.
  • Receipts with model, usage, and a versioned price estimate. Unknown cost stays null. It is not stored as zero.
  • A hosted fleet UI with org sign-in, enrollment, and alerts. Billing stays off until a Stripe readback exists.
  • costcap check as a composite GitHub Action. No Marketplace listing and no npm publish yet.

Buyer and offer

Proposed buyer: someone running proxy-routed agents who wants a hard local stop and a receipt they can reconcile. The MIT CLI is free. The hosted dashboard is a proposed $19 per month. That figure is not collected revenue.

Limits

  • Only traffic that honors the wrapper's base URL is metered. Hardcoded endpoints bypass it.
  • A single call can finish above the remaining budget. This is not a prepaid hold.
  • Prices are estimates. They are not the provider invoice.
  • Live login proof, DNS for costcap.dev, Postgres in production, and npm publish are blocked on credentials.
